# 第二周任务分工

## 1. 本周目标

上一周已经完成学生业务链和教师业务链向新版主链 `course -> course_section -> enrollment -> score` 的切换，并达到最低可运行、可联调、可演示标准。

本周目标从“证明学生/教师主链可跑通”切换为“补齐管理员端新版业务链，并同步推进数据库加分项、残留清理和交付材料准备”。管理员端本周不再作为附属页面处理，而是作为新版业务链的源头管理入口。

本周优先级为：

1. 管理员端课程、教学班、院系、专业、教室 CRUD 页面可运行。
2. 后端管理员接口和前端管理员页面按新版 `course + course_section` 语义完成联调。
3. 学生端、教师端保持已跑通链路稳定，并清理旧接口、旧页面和误导性入口。
4. 数据库侧继续补齐约束、索引、触发器、视图、测试数据和性能证明材料。
5. 组长 A 同步沉淀设计说明、验收证据和最终报告素材。

## 2. 共享前置决策

1. 学生业务链和教师业务链上一周已完成最低验收，本周默认作为稳定基线维护。
2. 管理员新业务链定位为：`管理员登录 -> 维护课程 course -> 开设/维护教学班 course_section -> 学生围绕教学班选课 enrollment -> 教师围绕选课记录录入 score`。
3. 管理员负责课程与教学班的创建、维护、关闭和基础数据管理；教师不承担开课或开班职责。
4. `course` 表示课程目录，`course_section` 表示某学期、某教师、某教室、某容量下的具体教学班。
5. 学生选课必须围绕 `sectionId`，成绩必须依附 `enrollmentId`，不得回退到旧的 `score` 兼任选课记录口径。
6. 已有选课记录的课程或教学班，优先做关闭、停用或状态变更，不建议直接物理删除。
7. 本周管理员端必须完成课程、教学班、院系、专业、教室的 CRUD 页面和接口可用闭环；统计看板、复杂筛选、批量操作和非核心美化可后置。

## 2.1 本周管理员完整版页面口径

本周管理员端最终至少形成 8 个页面或模块：

1. 管理员首页 / 数据概览：展示学生总数、教师总数、课程总数、教学班总数、选课记录总数、已录入成绩数；优先保证真实统计数据，图表后置。
2. 课程管理：管理课程目录 `course`，支持课程列表、新增课程、编辑课程、停用或删除课程，并支持按课程名、院系、状态筛选；页面语义不能再把 `course` 当成学生可直接选择的教学班。
3. 教学班管理：本周核心页面，支持教学班列表、新增教学班、编辑教学班、关闭教学班、查看已选人数；新增或编辑表单必须包含课程、教师、教室、学期、容量和状态。
4. 学生管理：维护学生基础资料和账号归属，至少保证页面能打开、列表能查、编辑能保存；新增或编辑学生时应能绑定 `major`。
5. 教师管理：维护教师基础资料和院系归属，至少保证页面能打开、列表能查、编辑能保存；新增或编辑教师时应能绑定 `department`。
6. 院系管理：维护 `department`，支持院系列表、新增、编辑、删除或停用；院系数据用于课程、教师、专业归属。
7. 专业管理：维护 `major`，支持专业列表、新增、编辑、删除或停用；专业必须绑定所属院系，并用于学生归属。
8. 教室管理：维护 `classroom`，支持教室列表、新增、编辑、删除或停用；教室数据用于创建教学班。

`department / major / classroom` 本周不再只作为下拉数据，必须做成可正常使用的 CRUD 页面：

- `department` 至少支持列表、新增、编辑、删除或停用，并能被课程、教师、专业页面引用。
- `major` 至少支持列表、新增、编辑、删除或停用，并能绑定 `department`，被学生页面引用。
- `classroom` 至少支持列表、新增、编辑、删除或停用，并能被教学班页面引用。

本周管理员端最终验收标准固定为：

1. 管理员能登录进入后台。
2. 管理员能维护课程目录。
3. 管理员能创建、编辑、关闭教学班。
4. 管理员能正常维护院系、专业、教室 CRUD 页面。
5. 管理员创建或修改的院系、专业、教室能在相关表单中被引用。
6. 管理员创建的教学班能出现在学生选课列表。
7. 学生选课后，该教学班 `selectedCount` 正确变化。
8. 教师能看到归属自己的教学班和学生名单，并继续录入成绩。

本周验收重点不是“管理员页面有按钮”，而是跑通 `管理员开班 -> 学生选班 -> 教师管班` 的闭环。

学生、教师编号规则以 `sql/generated_data_new.sql` 为准：

- 学号：`S + department_code + enrollmentYear + 4位序号`，例如 `SCS20250001`。
- 工号：`T + department_code + year + 4位序号`，例如 `TCS20250001`。
- `department_code` 使用院系代码，如 `CS`、`MATH`、`ECON`；学生侧通过 `majorId -> department_id -> department_code` 推导，教师侧通过 `departmentId -> department_code` 获取。
- 默认登录账号等于生成的学号或工号，默认密码为 `123456`。

后续 D 接学生/教师管理页面时，不再让管理员填写或选择 `userId`；页面只负责专业/院系、年份、姓名、联系方式等业务字段，并可通过 C 提供的编号预览接口预填学号、工号、登录账号和默认密码。
